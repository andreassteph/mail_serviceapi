# Mailclient service API

Generated by `tools/service_api_docs.py` from [service-api.openapi.json](./service-api.openapi.json): never edit by hand.

Version 0.9.1, OpenAPI 3.1.0.

REST API for scripts and backend services: read mail, sort it into categories, create drafts. Every request is scoped to one user named in the path. Scripts and assistants that prefer tools use the MCP server instead, which offers the same capabilities with the same rules (see the guide "REST or MCP" in the documentation).

## Authentication

- `bearerAuth` (http): A personal token (Einstellungen, API-Tokens) or the access token of a service client. Paste the token without "Bearer".
- `oauth2` (oauth2): Service client with a secret: client credentials. Enter client id and secret and select the scopes.
  - token URL: `/oauth/token`
  - scope `mails:read`: List and read mails, attachments, the original message, images and the change log
  - scope `mails:categorize`: Set the categories of a mail
  - scope `categories:read`: List categories
  - scope `categories:write`: Create and change categories
  - scope `drafts:write`: Create drafts (never sends mail)

### GET `/api/v1/service/users/{user}/mails/{key}`

Read one mail (`getMail`)

One mail in full: the list fields plus the clean body for AI processing (`bodyCleanMarkdown`), recipients, images and attachment metadata. Reading does not mark the mail as read. With `includeFullMarkdown` the answer adds `bodyMarkdown`, the body as sent, for showing the mail to a person. With `includeRaw` the answer adds `raw`, the original message; its `bodyHtml` is untrusted input. Attachment text, the change log and the .eml have their own operations. MCP equivalent: `get_mail`, which returns attachment text and history in the same answer.

Scopes: `mails:read`

| Parameter | In | Type | Required | Description |
|---|---|---|---|---|
| `user` | path | integer | yes | Id of the user whose mail to use (see GET /users). |
| `key` | path | string | yes | The mail key from list_mails (22 characters, permanent). |
| `includeFullMarkdown` | query | boolean | no | Add bodyMarkdown, the body as the sender sent it with links, image references, signature and quoted reply, for showing the mail to a person. Leave it out for AI processing: bodyCleanMarkdown, always included, is the better and much smaller input. E.g. true. Default: `false`. |
| `includeRaw` | query | boolean | no | Add the original message (raw: status, size, fetchedAt, bodyHtml, bodyText, url). E.g. true. Default: `false`. |
| `maxBodyChars` | query | integer | no | With includeRaw: cut bodyHtml and bodyText of raw after about this many characters, e.g. 5000. bodyMarkdown and bodyCleanMarkdown are not cut. Default: `20000`. minimum: 1000. maximum: 100000. |

Responses:

- `200` [MailDetail](#maildetail): The mail.
- `401` [Error](#error): No valid bearer token (`unauthenticated`).
- `403` [Error](#error): The credential lacks the scope of this operation (`scope_missing`), has no grant for this user (`user_not_allowed`) or the IP address is not allowed.
- `404` [Error](#error): No such mail for this user (`unknown_key`); another user's mail looks the same.
- `422` [Error](#error): An argument is invalid (`invalid_argument`).
- `429` [Error](#error): Too many requests (`rate_limited`); wait the number of seconds in the Retry-After header.

### PUT `/api/v1/service/users/{user}/mails/{key}/categories`

Set the categories of a mail (`categorizeMail`)

Sets the full set of categories, replacing the previous ones; `[]` makes the mail uncategorized. Idempotent; the last edit wins, also over the user's own choice. A category passed together with one of its subcategories keeps only the subcategory (`droppedCategories`). If one of the categories moves mail automatically and they point to one folder, the mail moves there (`movedTo`, done on the mail server at the next sync); several folders answer `moveConflict` and nothing moves. MCP equivalent: `categorize_mail`; `move_to_category_folder` resolves a conflict (MCP only).

Scopes: `mails:categorize`

|---|---|---|---|---|

| `key` | path | string | yes | The mail key from list_mails (22 characters, permanent). |

Request body (`application/json`):

| Field | Type | Required | Description |
|---|---|---|---|
| `categories` | list[string] | yes | The mail's categories by full path, e.g. ["Rechnungen/Strom"]; [] for none. |
| `categorizedBy` | string | no | Who decided, remembered on the mail, e.g. "llm" or "heuristic". Lowercase letters, digits and _ . : -, max 32. "user" and "system" are reserved. Default: `"api"`. |

Responses:

## Drafts

Drafts for the user to review and send.

### POST `/api/v1/service/users/{user}/drafts`

Prepare an answer as a draft (`createDraft`)

Creates a draft for the user, who finds it in the app (Entwurf), edits it and sends it. This operation never sends mail. To answer a mail pass `replyTo`: recipient, subject ("AW: ...") and account are taken from that mail unless you set them. For a new mail pass `account`, `to` and `subject`. Each mail has at most one draft and there is one draft for a new mail; an existing draft is never overwritten unless `replace` is `true`. MCP equivalent: `create_draft`.

Scopes: `drafts:write`

| Parameter | In | Type | Required | Description |
|---|---|---|---|---|
| `user` | path | integer | yes | Id of the user whose mail to use (see GET /users). |

Request body (`application/json`):

| Field | Type | Required | Description |
|---|---|---|---|
| `body` | string | yes | The text of the answer, plain text, up to 200000 characters. maxLength: 200000. |
| `replyTo` | string | no | The key of the mail to answer, from list_mails (22 characters). Leave out for a new mail. |
| `account` | string | no | The mailbox to send from, by its name, e.g. "Privat". Optional for a reply (the mail's own mailbox), required for a new mail. |
| `to` | string | no | Recipient addresses, comma separated, at most 20, e.g. "kunde@example.com". Optional for a reply (the sender of the mail), required for a new mail. maxLength: 5000. |
| `subject` | string | no | Subject line without line breaks, e.g. "AW: Angebot". Optional for a reply (AW: plus the mail's subject). |
| `category` | string | no | One category by full path from list_categories that the sent mail gets, e.g. "Rechnungen/Strom". Optional; the user can still choose. |
| `replace` | boolean | no | true overwrites an existing draft for this mail (or for a new mail). Default false: an existing draft is kept and the call fails. Default: `false`. |

Responses:

- `201` [Draft](#draft): The draft was created.
- `401` [Error](#error): No valid bearer token (`unauthenticated`).
- `403` [Error](#error): The credential lacks the scope of this operation (`scope_missing`), has no grant for this user (`user_not_allowed`) or the IP address is not allowed.
- `404` [Error](#error): No mail with the key in `replyTo` (`unknown_key`).
- `409` [Error](#error): The mail (or a new mail) already has a draft (`draft_exists`); send `replace: true` to overwrite it.
- `422` [Error](#error): An argument is invalid: `invalid_argument`, `missing_argument`, `invalid_recipient`, `too_many_recipients`, `invalid_subject`, `body_too_long`, `unknown_account`, `unknown_category` or `ambiguous_name`.
- `429` [Error](#error): Too many requests (`rate_limited`); wait the number of seconds in the Retry-After header.

## Authentication

Token endpoint for service clients.

### POST `/oauth/token`

Get an access token (service clients) (`requestToken`)

A service client exchanges its credentials for a short-lived access token (10 minutes) with the **client credentials** grant. Send the client secret, or, for a client with a public key, a signed JWT (`private_key_jwt`) as `client_assertion` instead of `client_secret`. The token is sent as `Authorization: Bearer <token>` on every other operation. The endpoint allows 10 requests per minute per IP and client. Personal tokens are created in the app and need no request.

Request body (`application/x-www-form-urlencoded`):

| Field | Type | Required | Description |
|---|---|---|---|
| `grant_type` | `client_credentials` | yes |  |
| `client_id` | string | yes |  |
| `client_secret` | string | no | The secret of the client; or use client_assertion. |
| `client_assertion_type` | `urn:ietf:params:oauth:client-assertion-type:jwt-bearer` | no |  |
| `client_assertion` | string | no | A JWT signed with the client's private key. |
| `scope` | string | no | Space separated scopes, e.g. "mails:read categories:read mails:categorize". |

Responses:

- `200` object: The access token.
- `400`: The request is malformed or the scope is not allowed (OAuth error body: `error`, `error_description`).
- `401`: The client could not be authenticated (OAuth error body).
- `429`: Too many requests.
